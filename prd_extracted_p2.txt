When the same (entity, metric, period) tuple has values from multiple sources that differ beyond tolerance, the bot must ask the user once during onboarding. Their answer is locked in for the entire session: subsequent queries about that metric never re-prompt. The locked-in choice is recorded in the citation envelope of every answer involving that metric, so the user can always see which source they chose.
If the user later wants to change the source-of-truth choice, they must re-upload the file or explicitly invoke a "reset source choices" command.
If the same conflict appears in a future session, the bot does NOT remember the prior choice — onboarding starts fresh. (This is intentional: stale choices are dangerous.)
If the user cannot decide and wants to see all values, the bot offers a "show all" option that displays every conflicting value with its citation in every relevant answer, instead of picking one.
7.3 Confident-Decision Disclosure Policy (v1.2)
Every confident interpretation decision — even ones the bot would handle without asking — is listed in the onboarding message. The user does not need to act on these (no questions are asked), but they are visible. This is the per-user-preference choice locked in at PRD level: full disclosure over silent application.
Unit conversions (Lakhs → Crore, INR absolute → Lakhs, etc.) are listed individually.
Paren-negative parsing is listed once per sheet where it occurred, with one example cell.
Total/subtotal rows that were stripped are listed by row label.
Mixed-unit row splits (e.g., Sharma Textiles' Other Exp Detail) are listed with the rows that were treated differently.
Period normalization is listed once per detected period grain.
If the message exceeds ~30 disclosure items, items are grouped into expandable categories ("15 unit conversions — tap to expand") to avoid overwhelming the user. Default state is collapsed for groups, expanded for individual items.

7.8 Edge Cases the Onboarding Engine Must Handle
User uploads a second file mid-session: each file gets its own onboarding message; cross-file conflicts (e.g., same company, different sources) are surfaced in the second file's onboarding.
User skips/ignores the blocking question and asks something else: bot must NOT answer; instead, it gently redirects to the unanswered question.
Validation fails (totals don't reconcile, units indeterminate): bot says so plainly and asks the user to upload a corrected version, rather than guessing.
Onboarding message would exceed ~30 disclosure items: items group into expandable categories. Conflicts (the blocking section) never collapse.
User answers a conflict question with something unparseable ("both" / "whatever" / off-topic): bot re-asks once, then asks them to choose A/B/C/D explicitly.
8. Success Metrics & UAT
User Acceptance Testing will be conducted against a "golden dataset" of historic documents. Success is defined by:
Accuracy
: 100% mathematical accuracy on explicitly requested numerical KPIs.
Latency
: End-to-end response times under 15 seconds.
Reliability
: The system must explicitly state when a document does not contain the required data, rather than estimating.
REVISION v1.1 — 
Two metrics sharpened, three added. (a) Accuracy is reframed as accuracy on approved facts; pre-approval staging facts are not in scope. (b) Latency is tiered by query class — simple lookups under 3s, derived metrics under 8s, multi-source reconciled answers under 15s. (c) Three new metrics: Ingestion Fidelity (% of test-corpus files where mapping is approved without human correction), Conflict Surfacing (% of seeded cross-source conflicts that the system flagged), and Hallucination Rate (% of responses containing any number not traceable to a citation envelope; target = 0%).
REVISION v1.2 — 
v1.2 adjustments. Accuracy is reframed against the user-acknowledged onboarding state, not a separate approval. Ingestion Fidelity is split into two: Auto-Onboarding Rate (% of files where the bot's onboarding message has zero blocking questions — pure disclosure, no conflicts) and Conflict Resolution Quality (whether the bot's conflict question was the right one to ask). Adds Onboarding Completion Rate (% of upload sessions where the user successfully reaches LIVE state, vs. abandoning at the conflict-question stage), which is the v1.2 product-health metric.
